设计哲学

内核很小，野心很大

核心只做三件事：加载插件、管理生命周期、格式化兜底。约 3700 行 Go 代码， 十个子模块，通过 JSON-RPC over stdio 与插件通信。 它不认识 AI、LLM、工具、UI——只认识 JSON-RPC 2.0 和 manifest.json。

capability

能力代理：默认拒绝

插件想读文件、发网络请求、开终端？必须在 manifest 里声明权限，否则一律拒绝（-32002）。配合路径围栏、审计日志、4MB 输出上限——AI 再能折腾，也出不了沙箱。

  • core.fs / core.net / core.shell / core.process 四族能力
  • 未声明权限 → 默认拒绝；路径围栏限制访问范围
  • 每个动作都留审计日志
原则：插件只有「借地方」的权利，用户永远有退路。
ui.page.*

插件自带界面

插件在 manifest 里声明 ui.page.<名字>.v1，实现 list / render / action / key 四个方法，就能拥有自己的页面。界面只负责「借地方」、转发点击与按键——Tab 键永远不转给插件。

  • 全屏 TUI + 行式降级两档自动选择，不依赖浏览器
  • 16 种终端尺寸/颜色组合用单测校验排版不变量
  • 插件没了，它的页面就没了——干净退场
细节：每行显示宽度精确等于终端宽度，一像素都不多。
ai-pipeline

AI 四件套链路

llm → toolExecutor → agent → session，四个插件串出完整的 AI 对话链路：界面 → session → agent → 工具执行 → 大模型 → 文件读取 → 能力代理。零配置可跑（离线 mock），支持 DeepSeek、Kimi、GLM、OpenAI、Gemini 等十余家云端 + Ollama/LM Studio 本机服务。

  • provider 协议跟着端点走：OpenAI 兼容 / Ollama 原生 / mock
  • /tool 命令逐层自省，实时看 AI 在调什么工具
  • 三个刻意取舍：缺插件不崩、预算可自定义、错误喂回模型
亮点：AI 不只是被使用——它还能自己给自己写插件。
pluginManager

让 AI 自己做插件

一条命令 /tool pluginManager.v1 create，AI 就能生成一个带 manifest、入口和界面的完整插件（Python 直接可用，Go 经 builder 编译）。builder 有严格安全边界：只执行写死的 go build，拒绝路径穿越。

  • 插件支持 binary / python / node / java / wasm 五种运行时
  • 生命周期状态机：pending → starting → active → degraded → dead
  • 4 种语言官方 SDK：Go / Python / Java / C
闭环：用 AI 做的平台，最终由 AI 自己扩展它。
